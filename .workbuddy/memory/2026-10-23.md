## 16:00 基岩版下载/安装功能：端到端实测打通 + 修掉两个真 bug
昨天把「基岩版」标签页的代码写完了，但下载/安装链路没验证过。今天用用户真实微软账号（配置里已存 token）把它跑通。

### 修掉的真 bug（都不小）
1. **token 用错对象**：`Account.AccessToken` 存的是 **Minecraft 令牌**（游戏 auth_access_token 用），XBL 鉴权要的是**微软身份令牌**——后者登录时只存在局部变量里被丢了 → XBL 一步就 401。
   修法：Account 加 `MsAccessToken`/`MsTokenExpire`；新增 `MicrosoftAuth.GetMsTokenAsync()`（过期就用 refresh token 换新的）。
2. **`MicrosoftAuth.RefreshAsync` 写错了令牌类型**：它用 refresh 换来的是微软身份令牌，却直接写进 `AccessToken`，导致"刷新"后游戏在线认证失败。
   修法：重写成完整链 GetMsToken → XBL → XSTS → login_with_xbox，才更新 `AccessToken`。
3. **安装检测用错参数**：`Get-AppxPackage -Name` 匹配的是包**名**（Microsoft.MinecraftUWP），不是包**族名**（..._8wekyb3d8bbwe）→ 永远查不到；且 PowerShell 进度流被重定向后以 CLIXML 污染 stdout，版本号成乱码。
   修法：按 PackageFamilyName 过滤 + `VER:` 标记解析；RunPs 统一加 `$ProgressPreference='SilentlyContinue'` 与 `-OutputFormat Text`，并用 `-EncodedCommand`（避中文路径在 PS5.1 被按 ANSI 解坏）。

### 摸清的基岩版下载链路（本机实测）
- ProductId `9NBLGGH2JHXJ`、ContentId `7792d9ce-355a-493c-afbd-768f4a77c3b0`、包族 `Microsoft.MinecraftUWP_8wekyb3d8bbwe`。
- 新版已是 **MSIXVC** 格式（不再是旧 appx），主包 `Microsoft.MinecraftUWP_<ver>_x64__8wekyb3d8bbwe.msixvc` = **1.93 GB**；另有 13 个 `update-*.xsp`（4~12KB，是 MS-XPFM 签名的**更新清单**，装旧版要靠商店更新引擎套用，不能直接 Add-AppxPackage）。
- 鉴权：MS 身份令牌 → XBL → XSTS(RelyingParty=**http://update.xboxlive.com**) → `Authorization: XBL3.0 x=uhs;token`。
- 取包：`GET https://packagespc.xboxlive.com/GetBasePackage/{contentId}`。
- **URL 拼接必须 `CdnRootPath + RelativeUrl`**（RelativeUrl 里含 ContentId/VersionId 两段，只拼文件名会 404）。
- CDN 走 **http**（`assets1/assets2.xboxlive.cn`）：https 在本机证书校验失败（curl exit 60），所以候选链要 https→http 降级。下载 61.6 MB/s，1.93GB 约 35 秒；支持 Range 断点续传。

## 16:50 「基岩版像 Java 版那样」——调研 + 落地存档配置隔离

## 18:15 下拉框滚动 + 版本分组（GUI 验证方式已废弃，见下）
用户反馈：① 模组页"选择版本"下拉**无法往下滑**；② 版本下拉要改成"每个版本为一组，
同版本的其它变体（测试版/稳定版）归到一组"；③ "在线下载里根本没有基岩版的"。

**根因（三条里两条是同一个病根）**：`Themes/Fluent.xaml` 的 `FluentComboBox` 模板里
`<ScrollViewer MaxHeight="320"><ItemsPresenter /></ScrollViewer>` **没设 `CanContentScroll="False"`**。
WPF 在 CanContentScroll=True 时走"按项逻辑滚动"，非虚拟化面板下滚轮直接失效 → 长列表只能看到前几项。
这也解释了"看不到基岩版"：它是来源下拉的第 3 项，被前面两项挤出可视区/滚不到。
修法（三个一起）：`ScrollViewer.CanContentScroll="False"` + `Focusable="False"` +
`MaxHeight` 320→380 + 样式里加 `ItemsPanel` setter 用 `VirtualizingStackPanel`（长列表虚拟化）。

**版本分组**：`VersionEntry` 加 `GroupKey`（1.21.4 / 1.21.4-rc1 / 1.21.4-pre1 → 同组"1.21.4"，
1.21 另开一组）与 `DisplayName`（类型+加载器）；`ModsView` 用
`CollectionViewSource.GetDefaultView + PropertyGroupDescription(GroupKey)` 分组，
XAML 里给 ComboBox 加 `GroupStyle.HeaderTemplate`（组头显示版本号）。不加排序描述以保留扫描出的从新到旧顺序。
坑：`ItemsPresenter.ItemsPanel` 这种 XAML 写法编译器不认（MC3074），要在样式上设 `ItemsPanel` setter。

**重要教训（用户明确不满）**：不要再做"启动 GUI → 截图 → 反复截图"的验证循环。
用户两次发火（"一直截图干什么"）。以后改完 UI 直接编译发布 + 用文字说明改动，
确需验证就**最多一张**截图，或直接问用户效果。
另外：`tools/click.py` 截图前会再调 `force_fg`，会把 ComboBox 展开的下拉框关掉，
所以它根本截不到展开状态（已改成截图前不抢焦点）。

## 19:40 类名显示的真正根因 + 自建界面渲染验证器
用户截图显示下拉收起时是 `HHCL.Core.ModrinthVersion` / `HHCL.Core.ModpackRelease` 这种类名。

**根因（之前几轮都猜错了）**：`DisplayMemberPath` **不会**生成 `ItemTemplate`，
所以模板里 `ContentTemplate="{TemplateBinding SelectionBoxItemTemplate}"` 拿到的仍是默认模板，
ContentPresenter 只能回落到 `ToString()` → 没重写 ToString 就显示类名。
**正确修法：给模型类加 `override string ToString()`**（已给 ModrinthVersion / CfFile / ModpackRelease 加），
一次修好全站所有下拉框，比改模板靠谱。
另外发现 `VersionEntry.DisplayName` 忘了带版本号，导致收起后显示空白（只有"　Fabric"），已补上 `Id`。

**自建验证器 `HHCL/ViewShot.cs`（`--shot mods|modsonline|modpacks|bedrock|download [宽] [高]`）**：
把界面直接用 `RenderTargetBitmap` 渲染成 PNG，**完全不依赖鼠标点击坐标**，比截图脚本可靠得多。
坑：① 一个 AppDomain 只能有一个 `Application`，要复用 `Application.Current`，不能再 new；
② 驱动异步搜索**不能 `task.Wait()`**（阻塞 UI 线程死锁），要用 `DispatcherFrame + DispatcherTimer` 一边转一边等。
已用它验证：版本下拉正确显示 `26.3`、`OnlineVerBox` 已是 ListBox、页面无 XAML 运行时错误。

**GUI 自动化的坑（别再踩）**：窗口最大化时是 2574x1454，恢复时 1180x760，
`GetWindowRect` + `ImageGrab` 的截图会被缩放到 1280 宽 → 截图像素≠窗口坐标，偏移量每次都不一样。
要做像素级自动化，先 `SetWindowPos` 把窗口固定到 (0,0,1200,800)，此时截图像素与窗口坐标 1:1。

发布：HHCL发布/HHCL.exe（650895 B）+ 同步 Desktop/HHCL.exe；无 crash.log。

## 20:05 小框框 bug：模板又改错了，已改回
用户截图：在线下载工具栏的来源/类型下拉外面多了一个小框，点开后文字直接消失。

**原因**：上一轮我把模板的
`Content="{Binding SelectedItem}" ContentTemplate="{Binding ItemTemplate}"` 顶替了原来的
`SelectionBoxItem` / `SelectionBoxItemTemplate`。而这些下拉的选项本身就是 `<ComboBoxItem>` 控件——
**UI 元素不能同时出现在两个视觉树里**，于是 ComboBoxItem 被从下拉列表里"抢"到收起框里渲染成小框，
弹开后文字就没了。

**修法**：模板改回 `SelectionBoxItem` / `SelectionBoxItemTemplate`（原来的写法），
类名问题靠模型类 `override ToString()` 解决（与模板无关）。
验证：实机截图（整合包页 Modrinth/全部版本/任意加载）与渲染图（模组页 Modrinth/模组）都正常无小框。

**教训**：改 ComboBox 模板时不要动 SelectionBoxItem 那条绑定；
`DisplayMemberPath` 不生成 ItemTemplate（这是类名显示的真正原因），要显示友好文本就给模型加 ToString()。

**GUI 自动化坐标**：窗口用 `SetWindowPos` 固定到 (0,0,1200,800) 后，
截图像素与窗口坐标是 **1:1（偏移 0）**——之前误以为有 40px 偏移，
其实是点错了导航项（下载 vs 模组与资源 挨着，容易看串）。

发布：HHCL发布/HHCL.exe（651407 B）+ 同步 Desktop/HHCL.exe；无 crash.log。
