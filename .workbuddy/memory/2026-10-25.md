## 08:30 联机房间加访问密码（真·主机侧校验）
**需求**：别人必须输入正确密码才能连上房间。

**为什么需要自己实现**：Minecraft「开放到局域网」用的是**集成服务器，没有密码**，
谁拿到地址谁就能进，官方没给这个开关。

**实现（HHCL/Core/LanAuth.cs，约 300 行）**：
- **主机端 `LanAuth.Server`**：本机监听代理端口（默认 45679，冲突就往后找，最多试 20 个），
  握手流程 `客机→"HHCL-AUTH/1\n"` → `客机→"<密码>\n"` → `主机→"OK\n"/"DENIED\n"`，
  通过后才连 `127.0.0.1:游戏端口` 并双向转发（认证阶段走自定义协议，之后是原始字节流）。
- **客机端 `LanAuth.Client`**：起本地代理 `127.0.0.1:0`（系统分配端口），游戏用
  `--quickPlayMultiplayer 127.0.0.1:本地端口` 连过来，代理再去连主机完成密码握手，
  通过后开始转发。**游戏连的是 127.0.0.1，所以 quickPlay 完全兼容**。
- 密码用 `CryptographicOperations.FixedTimeEquals` 比较（防时序侧信道），长度不同也走完比较。
- **没开密码时行为和以前完全一样**（直连游戏端口），零影响老用法。

**已知边界（UI 里写清楚了）**：同一局域网内，别人若直接填**游戏端口（房间码）**仍可能绕过密码
（集成服务器自己监听 0.0.0.0，拦不住）。跨网场景只映射代理端口就安全。
彻底封死要动 Windows 防火墙（需管理员），本次没做。

**UI 改动**（Views/LanView.xaml + .xaml.cs）：
- 主机区：加「访问密码」复选框 + 输入框 + 「随机」按钮（默认随机 6 位数字）
- 房间信息卡片：加密码行 + 「复制密码」按钮；开密码时联机地址显示的是**代理端口**不是游戏端口
- 客机区：加「房间密码」输入框 + 「粘贴密码」按钮；密码错会明确提示「密码不对，连不上」

**自测**（`tools/LanAuthTest/`，用 `<Compile Include="..\..\HHCL\Core\LanAuth.cs" />` **直接链接真实实现**
+ stub 一个 `HHCL.Core.Log` 免得依赖 WPF）4 项全过：
正确密码连通 / **错误密码被拒且数据到不了游戏服务器（游戏服务器连都没连上）** / 空密码照常 / 垃圾协议回 BAD。

**发布**：`HHCL发布/HHCL.exe` 733,839 B → 覆盖桌面（旧版备份为 `HHCL发布/HHCL-上一版-<日期>.exe`）；
自包含版 131,890,242 B → 重新打 zip → 分享包三个文件更新。

**GitHub 推送（重要突破）**：
- 之前一直以为「只有浏览器能带认证访问 GitHub」，**错**：
  **`git ls-remote https://github.com/...` 直连是通的**（curl 直连 api.github.com 不通，但 git 协议通！）
  → 所以代码推送直接用 `git push --force origin master`（URL 内嵌 token），**不用再绕 API 建 blob**。
  - 注意：**浏览器内 eval 传 75KB base64 会 "Argument list too long"**（Windows 命令行 32KB 上限）。
  - 远端 master 原是 API 重建的 `7827605c`（内容一样、sha 不同），force push 后统一为本地 `c92f6b4`。
  - `v1.0.0` tag 仍指向旧的 `7827605c`（不动，Release 关联不受影响）。

## 08:42 密码框的"默认密码 + 一堆空格删不掉"
**用户反馈**：密码框里有一大堆空格删不掉；要求去掉默认密码，改成提示"请填入密码"。

**改动**（Views/LanView.xaml + .xaml.cs）：
- 不再自动填随机密码（`PasswordCheck_Changed` 里去掉自动赋值），输入框留空，
  `Tag`（= watermark）改成「请填入密码」；想要随机再点「随机」按钮。
- 取消勾选时 `PasswordBox.Clear()`，不残留旧密码。
- 新增 `PasswordBox_TextChanged`：首尾 + 中间的空格/制表/换行全清掉，光标停在末尾
  （两个密码框共用这个处理器；单测 7 例全过：前导/中间/尾部空格、\t\n、全角数字不动、普通密码不动）。
- 客机区「房间密码」框的 watermark 也统一成「请填入密码」。

**关于"空格"的判断**：多半不是真有空格字符，而是**输入框内容左对齐 + Padding 11px**，
框内有值时点击会跳到文字末尾，看起来"前面空了一块还删不掉"。去掉默认值后框是空的，
watermark 居中显示，点击位置不再有歧义。TextChanged 兜底清空白，两手都做。

**这次踩的 UI 自动化坑（记下来省得再试）**：
- `uiautomation` 的 `WindowControl(SubName="HHCL")` 匹配到的是**Chrome**（GitHub 页面标题里含 HHCL），
  不是应用 → 必须**按进程名/PID 筛**（tasklist 拿 HHCL.exe 的 PID → EnumWindows 比对）。
- 侧栏「联机」和页面里其它控件都叫「联机」，`auto.Control(SubName=...)` 会选错 →
  要按 depth / BoundingRectangle 区分。
- 你的 Chrome 是**全屏置顶**（-8,-8 2576x1408），会抢走鼠标点击和焦点 →
  `SetForegroundWindow` 成功但点击仍落到 Chrome 上；截图用 ImageGrab 也会截到 Chrome。
  可靠截图法：**PrintWindow(hwnd, memdc, 2)**（能抓 WPF 内容，不受遮挡）。
  PrintWindow 封装在 `tools/grabwin.py`（这次用完删了，可再写）。
- `SetWindowPos` 对这个 WPF 窗口**不生效**（坐标不变），别指望靠移动窗口来避开遮挡。

## 08:50 输入框"右边空一大片"（全局 16 个输入框都有）
**用户反馈**：客机区「直连地址」「房间密码」框前面/后面有一大堆空格，"有很多这样子的"。

**根因（用 UIA 读到实测数据）**：这些 TextBox 放在 Grid 的 `*` 列里 → 被拉到 **823px 宽**
（窗口才 1180px），而内容就几十像素，**右边全是空白**。16 个 FluentTextBox 里
只有 4 个显式设了 Width（MemMax 110 / MemMin 110 / Width 90 / Height 90）。

**改法**：
- `Themes/Fluent.xaml` 的 `FluentTextBox` 样式加 `MaxWidth=400` + `HorizontalAlignment=Left`
  → **一处生效，全局 16 个输入框都不再撑满**（已设 Width 的不受影响）。
- 联机页三个框给精确宽度：直连地址 300、主机密码 220、客机密码 220。
- 「直连地址」框也接上 `InputBox_TextChanged` 去空白（之前只有两个密码框有）。
- `PasswordBox_TextChanged` 改名 `InputBox_TextChanged`（三个框共用）。

**验证（PrintWindow 抓图，这次真的截到了）**：

- 联机页主机页：占位「请填入密码」✓、宽度正常 ✓、**"给朋友的话"那块不见了** ✓
- 联机页客机页：直连地址 300px、房间密码 220px + 占位「请填入密码」✓

**UI 自动化的关键经验（这轮终于跑通了）**：
1. **按 PID 找窗口**：`tasklist /FI "IMAGENAME eq HHCL.exe"` 拿 PID → EnumWindows 比对
   （`uiautomation` 的 `SubName="HHCL"` 会匹配到 Chrome，因为 GitHub 页面标题里含 HHCL）。
2. **点击必须用 UIA 读到的真实 rect**，别自己推算：侧栏「联机」的 RadioButton
   rect=(696,620,909,660)，我按截图比例猜的 y=604 偏了 40px，点的其实是「整合包」。
   「加入房间（朋友）」rect=(1118,467,1288,497) → 点 (1150,482) 才对。
3. **先最小化 Chrome**（`ShowWindow(hwnd, 6)`）再操作，否则全屏置顶的 Chrome 抢焦点和点击。
4. **PrintWindow(hwnd, memdc, 2)** 能抓 WPF 内容，不受遮挡；ImageGrab 会被 Chrome 盖住。
5. **64 位下 ctypes 调 GDI 必须显式 argtypes**（`CreateCompatibleDC`/`CreateCompatibleBitmap`/
   `SelectObject`/`GetDIBits`/`PrintWindow`/`GetWindowDC`），否则 "int too long to convert" 溢出。
   封装在 `tools/page_shot.py`（保留，以后切页截图直接用：`page_shot.py <标签> <屏幕y>`）。

## 09:05 输入框内容"居中"（真·空格的元凶）+ 删掉两个「粘贴」按钮
**用户反馈**："还是这样子，有空格"（截图里输入 `3`/`2`，字符飘在框中间），并让去掉旁边的「粘贴」。

**真因（这次是元凶，跟上两轮猜的都不一样）**：
`FluentTextBox` 样式只设了 `VerticalContentAlignment=Center`，**没设 `HorizontalContentAlignment`**，
模板里的 `PART_ContentHost`（ScrollViewer）也没设水平对齐 → **内容默认居中显示**。
所以"前面一堆空格"是**居中留白**，不是真有空白字符（但 trim 兜底也保留，双保险）。

**修法（三重钉死）**：
- 样式加 `<Setter Property="HorizontalContentAlignment" Value="Left" />`
- 模板里 `PART_ContentHost` 加 `HorizontalAlignment="Left"` + `HorizontalContentAlignment="Left"`
- 顺带 `MaxWidth=400` + `HorizontalAlignment=Left`（上一轮加的，防撑满）

**删掉的东西**：客机区「直连地址」旁的「粘贴」和「房间密码」旁的「粘贴密码」两个按钮
（剪贴板里一般也不是这两样），连 `Paste_Click` / `PastePwd_Click` 一起删。
Grid 的第三列（Auto）也去掉了。

**验证（这次真的用键盘敲了字）**：`keybd_event` 打 `39` → PrintWindow 抓图 → 字符紧贴左边框 ✓
（`SendInput` 的 KEYEVENTF_UNICODE 对 WPF 无效，**要用 `keybd_event` 逐字符**）
封装在 `tools/utype.py`（Unicode 版可留备用）。

**发布**：桌面 HHCL.exe **733,839 B（09:09）** —— 比上一版 734,351 **小**，因为删了两个按钮 ✓
（「粘贴密码」字符串在二进制里 grep 计数 = 0，可用来验证改动到位）
分享包 exe/zip + 桌面副本同步更新。GitHub 推 `7149f30`。

**发布纪律（记忆里的坑）**：每次改完必须 `dotnet publish` → 拷 `HHCL发布/HHCL.exe` 到桌面。
**只拷 `bin\...\publish\` 里的会拿到旧产物**；`grep -c "关键字符串"` 可验证版本对不对。
